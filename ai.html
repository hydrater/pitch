Multi-Agent System

Specialized Agents

Each stage of the pipeline is handled by a purpose-built AI agent with specific instructions and access to prior results

Strategy Agent

Receives an archetype (e.g. "mean reversion using RSI") and writes a complete optimizer from scratch. Self-reviews against 23 documented bias patterns before execution. Runs up to 3 rounds, with each round narrowing parameter ranges around the best results from the previous.

Research Agent

Activated when built-in archetypes are exhausted. Reads every passed strategy, every failure post-mortem, and the aggregated failure statistics. Generates 10 novel strategy ideas per round that specifically avoid known failure patterns and target gaps in the current portfolio. Each idea includes explicit differentiation from previously attempted strategies.

Post-Mortem Agent

Analyzes each failed strategy in depth. Was the signal logic flawed? Were parameter ranges too narrow? Did the exit rules cause problems? Identifies near-misses (strategies that failed on a single metric) and quantifies how far each metric fell from the threshold. Writes a root cause analysis that feeds directly into the research agent's next round of ideas.

Alignment Agent

Verifies that the live trading engine produces identical results to the optimizer by comparing trade count, P&L, and drawdown within tight tolerances. If there's a mismatch (common due to execution timing differences), a specialized debugging agent traces and fixes the discrepancy.

Ensemble Agent

Combines multiple passed strategies into a single portfolio using a shared-capital simulation model. Optimizes member weights through iterative hill climbing across hundreds of configurations. Penalizes correlated strategies and enforces diversification constraints to ensure the ensemble is more resilient than any individual member.

Hedge Agent

Creates an all-weather defensive allocation layer that sits underneath the strategy portfolio. Uses regime-based asset allocation to shift capital between growth and defensive positions depending on market conditions. Targets near-continuous time-in-market to avoid cash drag while maintaining protection during drawdowns.

Code Integrity

Bias Review Framework

Every strategy is reviewed against 23 documented bias patterns before it can run. These patterns are categorized into four classes, each targeting a different way backtests can produce misleading results.

Execution Model

5 checks

Biases in how trades are filled. Incorrect entry/exit timing, same-day re-entry lookahead, and fill bar assumptions that would not hold in live trading.

Metrics Calculation

3 checks

Errors in how performance is measured. Drawdown tracked only at trade close instead of every bar, missing commission deductions, and win rate miscounting flat days.

Lookahead & Data

8 checks

Using future information that would not be available at decision time. Accessing next-bar indicator values, using close prices at market open, leveraged ETF split history, and data source mismatches between optimizer and engine.

Alignment

7 checks

Divergence between the optimizer and the live engine. Shared-capital vs return-weighted model differences, cross-symbol accounting errors, and execution model mismatches that cause results to drift over time.

Selection Criteria

Quality Gate

Every strategy must pass a battery of statistical and risk-adjusted tests simultaneously. Failing a single metric sends the strategy to post-mortem analysis. Thresholds tighten at the ensemble level.

Growth Minimum annualized return threshold
Downside Risk Maximum allowable peak-to-trough loss
Statistical Significance Returns must be distinguishable from random chance
Risk-Adjusted Return Performance measured relative to volatility and drawdown

Infrastructure

Pipeline Robustness

The pipeline is designed to run unattended for days. Built-in recovery mechanisms handle failures at every level.

🔄

Crash Recovery

Corrupted JSON files are auto-repaired, stale entries are recovered, and lock files are cleaned on startup. Failed agents auto-restart up to 3 times before escalating.

💾

Checkpointing

Long optimization runs (30,000+ configurations) checkpoint progress periodically. If a run is interrupted, it resumes from the last checkpoint rather than starting over.

⏱

Concurrency & Timeouts

Multiple strategy agents run in parallel with configurable concurrency limits. Each agent has a 2-hour timeout to prevent runaway processes from blocking the pipeline.

🔍

Monitoring Loop

A master orchestrator continuously monitors all active agents and layers. When enough strategies pass, it automatically triggers ensemble construction.
